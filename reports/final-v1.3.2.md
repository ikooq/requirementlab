- Решение аналитика: pending

## 6. Итог

- **Можно ли начинать разработку:** Нет
- **Можно ли начинать тестирование (проектирование тестов):** Нет

Разработка и тестирование не могут быть начаты из-за наличия critical-дефектов, блокирующих реализацию. Выявлены прямое противоречие между целями и требованием Ф-2 по моменту учёта операций (F-017), расхождение между Ф-2 и таблицей критериев приёмки (F-004), а также использование метода GET для мутации (F-007), конфликт статусов 403/404 (F-010) и возврат HTTP 200 OK при ошибках (F-011) в REST API.

Правило решения: есть хотя бы одно критичное нарушение — «Нет»; есть только существенные — «С оговорками». Модель не может ослабить это решение.

### Что исправить в первую очередь

1. Устранить критические противоречия в бизнес-логике и критериях приёмки (согласовать момент учёта операций и правило определения месяца). (F-004, F-017)
2. Исправить архитектурные ошибки API: изменить HTTP GET на POST/PUT для метода сохранения порога и согласовать HTTP-коды ответа (200, 400, 403, 404). (F-007, F-010, F-011)
3. Дополнить спецификацию API и модель данных отсутствующими эндпоинтами и атрибутами (чтение настроек, тип операции, родительская покупка). (F-008, F-020)
4. Описать неполные сценарии бизнес-логики (валютные операции, отмена авторизации/сторно, снижение порога ниже текущих расходов, значение по умолчанию). (F-003, F-005, F-018, F-021)
5. Унифицировать типы данных и единицы измерения атрибутов в спецификации API и хранилище (тенге/тиыны, integer/string). (F-006, F-012, F-013, F-014, F-015, F-016)
