## 6. Итог

- **Можно ли начинать разработку:** Нет
- **Можно ли начинать тестирование (проектирование тестов):** Нет

Начинать разработку и тестирование нельзя из-за критических архитектурных и логических дефектов. Обнаружены критические противоречия: изменение данных спроектировано через GET (F-008), успешный HTTP-статус 200 возвращает тело с ошибкой (F-016), а маскировка чужой карты противоречит коду 403 (F-011). Также выявлены конфликты типов данных в API (F-017, F-018) и несоответствие единиц хранения и передачи (F-004).

Правило решения: есть хотя бы одно критичное нарушение — «Нет»; есть только существенные — «С оговорками». Модель не может ослабить это решение.

### Что исправить в первую очередь

1. Исправить HTTP-метод для сохранения настроек с GET на PUT/POST и исключить передачу параметров через query в теле с application/json. (F-008, F-015)
2. Устранить противоречие по статусам ответа: перенести бизнес-ошибки на код HTTP 400 вместо статуса 200. (F-016)
3. Разрешить противоречие по маскировке чужих карт: привести код ответа в соответствие с требованиями ИБ и заголовком 403. (F-011)
4. Согласовать типы данных параметров amount и enabled в запросе и ответах API. (F-017, F-018)
5. Доработать требования к данным для хранения возвратов и связи операций, а также устранить расхождения в единице измерения порога. (F-004, F-005, F-023)
6. Заполнить обязательные атрибуты спецификации (версия, дата, Prod URL, Swagger, чек-листы ревью). (F-025, F-026, F-028)
