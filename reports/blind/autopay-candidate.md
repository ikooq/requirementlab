## 6. Итог

- **Можно ли начинать разработку:** Нет
- **Можно ли начинать тестирование (проектирование тестов):** Нет

Начинать разработку и проектирование тестов нельзя из-за критических противоречий в требованиях (F-002, F-011, F-023, F-024, F-037, F-038). Обнаружены несоответствия лимитов суммы, правил повторных попыток списания, логики авторизации, кодов ответа API и дат списания. Все выявленные критические дефекты требуют устранения до передачи в работу.

Правило решения: есть хотя бы одно критичное нарушение — «Нет»; есть только существенные — «С оговорками». Модель не может ослабить это решение.

### Что исправить в первую очередь

1. Устранить противоречия в лимитах суммы автоплатежа между бизнес-требованием Ф-1 и спецификацией API. (F-002)
2. Разрешить противоречие между запретом повторных попыток (Ф-3) и требованием повторять попытки три раза (Ф-5). (F-011)
3. Согласовать требования по авторизации и проверке сессии с настройками безопасности REST API. (F-023)
4. Устранить расхождение кодов статуса ответа API (400 и 409) при наличии активного автоплатежа. (F-024)
5. Привести в соответствие день списания в бизнес-требованиях Ф-2 и допустимый диапазон в параметрах API. (F-037, F-038)
6. Исправить формат даты nextDate в спецификации и примерах ответов API. (F-034)
7. Заполнить обязательные служебные поля документа (версия, чек-лист, Swagger, продуктивный URL). (F-039, F-040, F-042, F-043)
