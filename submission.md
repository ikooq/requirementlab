# RequirementLab — текст для подачи

**Репозиторий:** https://github.com/ikooq/requirementlab
**Отчёт агента:** `reports/report.md` (и `reports/report.json`), приложен к подаче
**Проверяемый документ:** `docs/requirements.md` из репозитория организаторов, приложен к подаче

## Коротко (1–2 предложения)

RequirementLab — AI-агент статического ревью требований по ISO/IEC/IEEE 29148 и IEEE 830. Он нарезает документ на требования, проверяет каждое и весь набор, а затем пишет отчёт на русском, где каждое нарушение подтверждено дословной цитатой с номером строки.

## Что получилось на документе кейса

- 27 требований, 40 нарушений, из них 4 критичных. Итог: разработку и тестирование начинать нельзя.
- Найдены все ключевые противоречия: Ф-3 и Ф-4 (лимит push), AC-2 и Ф-2 (месяц покупки), цель «в момент покупки» против учёта только проведённых покупок, суммы в тиынах против порога в тенге, сохранение через GET, ответ 200 с `ERROR` вместо 400, типы `amount`/`enabled` в запросе и ответе, 403/404, отсутствующий метод чтения настроек.
- Качество измерено: мы собрали эталон из 41 дефекта кейса, и отчёт находит 37 из 41 (90%) и все 6 критичных. 35 дефектов эталона составлены вручную до прогонов агента, по ним результат 31 из 35 (89%); ещё 6 — находки агента, которых не было в эталоне и которые подтвердились при проверке по документу. Скрипт оценки лежит в репозитории (`eval/score.py`).

## Чем решение отличается

1. **Проверяемые цитаты.** Агент сам находит каждую цитату модели в документе и вычисляет строку. Находки, для которых цитата не нашлась, в отчёт не попадают, а показываются в приложении с причиной отсева.
2. **Детерминированный итог.** Решение «можно ли начинать» принимает правило, а не модель: есть критичное нарушение — «нет».
3. **Второй ревьюер.** Отдельный проход модели снимает ложные срабатывания и дубли и перепроверяет каждое «не определено» по всему документу.
4. **Два независимых прохода.** Модель от прогона к прогону ловит немного разные дефекты; агент проверяет документ дважды и объединяет находки: 89% против 80% у одного прохода (по 35 дефектам, собранным до прогонов).
5. **Правила без LLM.** Заглушки, пустые таблицы, незаполненный чек-лист, отсутствие версии находятся детерминированно.
6. **Любой формат.** MD, TXT, PDF и DOCX; таблицы PDF восстанавливаются целиком, включая пустые ячейки.
7. **Надёжность на бесплатном тарифе.** Несколько ключей, запасные модели, кэш ответов; перегрузку сервера агент пережидает.

## Как воспроизвести

```bash
git clone https://github.com/ikooq/requirementlab && cd requirementlab
python -m pip install -r requirements.txt
cp .env.example .env            # Windows: copy .env.example .env — впишите GEMINI_API_KEY
curl -L --create-dirs -o docs/requirements.md https://raw.githubusercontent.com/BCC-HUB/ai-requirements-validator-task/main/docs/requirements.md
python run.py docs/requirements.md reports/report.md
```

Ключ Gemini бесплатный: https://aistudio.google.com/apikey. Отчёт ляжет в `reports/report.md`, данные — в `reports/report.json`.
