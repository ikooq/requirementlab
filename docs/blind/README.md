# Слепая проверка: как сделать независимый документ

Проверка честная, только если документ и эталон писал человек, который **не видел промптов агента** (`reqlab/prompts.py`) и не читал его отчётов. Автор `autopay.md` промпты знал, поэтому этот документ — полуслепой. Нужен ещё один документ от напарника.

## Что сделать напарнику

1. **Не открывайте** `reqlab/` и `reports/`. Документ кейса `docs/requirements.md` можно смотреть: он задаёт шаблон.
2. Напишите ТЗ на другую банковскую функцию по тому же шаблону: часть A (общие сведения, цели, UI, BPMN, функциональные и нефункциональные требования, данные, интеграция, критерии приёмки, чек-лист ревью, согласующие) и часть B (REST-метод: общие параметры, логика, параметры, ответ, статусы, примеры). Объём — 120–200 строк. Подойдут, например, лимит на снятие наличных, заморозка карты, перевыпуск карты, кэшбэк по категориям.
3. Заложите 20–35 дефектов **разных видов**, как в настоящих ТЗ: противоречия между требованиями, между частями A и B, между таблицей и примером; непроверяемые формулировки; пропущенные сценарии ошибок и граничных случаев; заглушки и пустые поля. Не подстраивайтесь под то, что, по-вашему, агент ловит хорошо.
4. Сохраните документ как `docs/blind/<имя>.md` и составьте эталон `eval/golden_<имя>.json` в формате [`eval/golden_autopay.json`](../../eval/golden_autopay.json):
   - `lines` — номера строк, где виден дефект (по файлу, нумерация с 1);
   - `keywords` — одна или несколько групп регулярных выражений; находка засчитывается, если её текст подходит под каждую группу. Делайте их достаточно широкими (синонимы, разные формы слов), иначе скрипт не засчитает найденный дефект;
   - `severity` — critical, major или minor.
5. Посчитайте SHA-256 документа и впишите в эталон:

   ```powershell
   python -c "from reqlab.loader import load; print(load('docs/blind/<имя>.md').sha256)"
   ```

6. Проверьте эталон тестом и **закоммитьте документ с эталоном до прогона агента**: коммит — доказательство, что эталон не подгоняли под результат.

   ```powershell
   python -m pytest tests/test_eval.py -q
   ```

## Прогон и оценка

```powershell
python run.py docs/blind/<имя>.md reports/blind/<имя>.md --brief
```

```powershell
python eval/score.py reports/blind/<имя>.json --golden eval/golden_<имя>.json -v
```

Результат публикуется как есть, вместе с пропусками. Эталон после прогона не меняют; если находка агента оказалась настоящим дефектом вне эталона, это пишут отдельной строкой, а не добавляют в эталон задним числом.

Чтобы тест проверял и новый эталон, добавьте его имя в `test_real_golden_is_valid` в [`tests/test_eval.py`](../../tests/test_eval.py).
