# Автоплатёж за мобильную связь

Пакет документов описывает новую функцию мобильного банка: регулярное пополнение баланса мобильного телефона с карты клиента. Часть A содержит бизнес-требования, часть B — описание REST-метода создания автоплатежа.

Документ подготовлен для проверки агентом требований и не используется в продуктивной разработке.

## Часть A. Новый функционал

### Общие сведения

| **Влияние на ИС** | Мобильный банк, платёжный шлюз, сервис регулярных платежей, SMS-шлюз |
| **Задача в JIRA** | PAY-0000 |

### Цели
Клиент один раз настраивает автоплатёж и больше не следит за балансом телефона: деньги списываются с карты автоматически каждый месяц, и номер не блокируется из-за нулевого баланса.

### Архитектура решения
Мобильный банк → сервис регулярных платежей → платёжный шлюз → оператор связи. Сервис регулярных платежей хранит настройки и запускает списания по расписанию.

### Дизайн процесса UI
Платежи → Мобильная связь → Автоплатёж. На экране поля «Номер телефона» (маска +7 XXX XXX XX XX), «Сумма, ₸», «День списания», выбор карты и кнопка «Подключить».

### Требования к изменениям

#### BPMN схема процесса
Наступление дня списания → проверка баланса карты → списание → зачисление оператору → SMS клиенту → завершение.

#### Функциональные требования
* **Ф-1.** Клиент подключает автоплатёж с любой своей карты на номер оператора Казахстана. Сумма — целое число от 100 до 50 000 ₸ включительно.
* **Ф-2.** Списание выполняется 1-го числа каждого месяца.
* **Ф-3.** Если на карте недостаточно средств, платёж в этом месяце не выполняется, повторных попыток нет. Клиент уведомляется.
* **Ф-4.** Клиент может приостановить автоплатёж и возобновить его в мобильном банке.
* **Ф-5.** При неуспешном списании система повторяет попытку три раза с интервалом в сутки.
* **Ф-6.** Клиент выбирает номер, сумму, день и карту, подтверждает подключение и получает SMS с подтверждением.
* **Ф-7.** На один номер телефона допускается один активный автоплатёж.

### Sequence Diagram
Мобильный банк → сервис регулярных платежей: создать автоплатёж. Сервис регулярных платежей → платёжный шлюз: списать сумму в день списания. Платёжный шлюз → оператор: зачислить сумму на номер.

### Нефункциональные требования
Списание выполняется быстро и надёжно. Сервис должен выдерживать высокую нагрузку в первый день месяца.

### Требования к данным
Хранится история списаний. Для каждого автоплатежа хранятся номер, сумма, день списания, карта и статус.

### Требования к интеграции
Платёжный шлюз возвращает результат списания синхронно. Оператор связи подтверждает зачисление в течение 5 минут.

## Часть B. REST API

Метод создаёт автоплатёж за мобильную связь.

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Создание автоплатежа. Функциональные требования: Ф-1, Ф-6, Ф-7 |
| **REST type** | POST |
| **Authorization** | Не требуется |
| **Controller** | AutopayController |
| **URL type** | Dev / Prod |
| **Request URL** | Dev: `/autopay/create` . Prod: — |
| **CURL** | `curl -X POST "$BASE/autopay/create" -H "Content-Type: application/json" -d '{"phone":"7011234567","amount":2000,"day":15,"cardId":"c-1"}'` |
| **Swagger** | — |
| **Gitlab project** | payments/autopay |
| **Framework** | Spring Boot |
| **Author** | Аналитик платежей |
| **Developer** | Команда платежей |

### Логика работы метода
1. Проверить пользовательскую сессию.
2. Проверить, что карта принадлежит клиенту.
3. Проверить номер, сумму и день списания.
4. Если на номер уже есть активный автоплатёж — вернуть 400.
5. Создать автоплатёж и вернуть его идентификатор и дату ближайшего списания.

### Параметры запроса

#### Request body

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `phone` | string | 10 | Да | 10 цифр без кода страны | Номер телефона | `phone` |
| `amount` | integer | 32 bit | Да | 1–5 000 000 | Сумма в тенге | `amount_kzt` |
| `day` | integer | 2 | Да | 1–31 | День списания | `pay_day` |
| `cardId` | string | 1–64 | Да | Карта клиента | Идентификатор карты | `card_id` |

### Ответ

| Parameter | Format | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `autopayId` | string | При успехе | Идентификатор автоплатежа | `autopay_id` |
| `nextDate` | string | DD.MM.YYYY | Дата ближайшего списания | `next_date` |

### Статусы

**200.** Автоплатёж создан.  
**400.** Некорректные параметры.  
**401.** Нет авторизации.  
**409.** Автоплатёж на этот номер уже существует.

#### 200. Successful
```json
{"autopayId":"ap-77","nextDate":"2026-12-01"}
```

#### 409. Conflict
```json
{"message":"Автоплатёж уже подключён"}
```
