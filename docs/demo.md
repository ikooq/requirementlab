# Сценарий демо (2–3 минуты)

Запись экрана: терминал слева, редактор с отчётом справа. Перед записью один раз прогнать агента на обоих документах: ответы модели лягут в кэш `.cache/llm`, и на записи прогон займёт секунды, а не 15 минут. В паспорте отчёта это будет честно указано («все из кэша»).

## 0:00–0:20. Задача

Сказать: «Аналитик пишет ТЗ, и дефекты в нём находят только на разработке. RequirementLab проверяет ТЗ до разработки по ISO/IEC/IEEE 29148 и IEEE 830 и отвечает, можно ли начинать».

Показать `docs/requirements.md` — документ кейса.

## 0:20–0:50. Запуск одной командой

```powershell
python run.py docs/requirements.md reports/report.md --brief
```

Показать вывод: число требований, нарушений и итог «разработку начинать: no».

## 0:50–1:30. Короткий отчёт и проверка цитаты

Открыть `reports/report-brief.md`: итог, 7 главных дефектов, что исправить.

Взять одну находку, например противоречие Ф-2 и AC-2. Найти её в `reports/report.md` по номеру F-…, взять строку из поля «Место» и открыть эту строку в `docs/requirements.md`. Сказать: «Цитату нашла не модель, а сам агент: находка без найденной в тексте цитаты в отчёт не попадает».

## 1:30–2:10. Качество измерено

```powershell
python eval/score.py reports/report.json
```

Сказать: «35 дефектов кейса мы собрали вручную до прогонов, агент находит 31 из них и все 6 критичных».

```powershell
python eval/score.py reports/blind/autopay.json --golden eval/golden_autopay.json
```

Сказать: «Чтобы проверить, что агент не подогнан под кейс, мы написали второй документ с 30 заложенными дефектами и закоммитили эталон до первого прогона. Результат на нём — вот эта цифра». Показать в `git log`, что коммит эталона раньше коммита отчёта.

## 2:10–2:40. Итог

Показать раздел «6. Итог» полного отчёта: «Нет» ставит правило, а не модель — модель не может смягчить решение при критичном дефекте.

Закончить: «Одна команда, любой формат (MD, PDF, DOCX), цитаты проверены, качество измерено на двух документах».
