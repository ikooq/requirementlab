# Разбор пропусков на документе об автоплатеже

Исходный отчёт набрал 22/30 по автоматическому сопоставлению. При разборе двух дополнительных пунктов нашлись точные цитаты в отчёте. Ниже указаны номера строк docs/blind/autopay.md.

| Эталон | Строки | Что произошло | Как проверять в других документах |
|---|---|---|---|
| B11 | 40 | Для сообщения о нехватке средств нельзя определить канал и момент доставки. | Из каждого обещанного результата вывести наблюдаемый исход для получателя. |
| B12 | 38 | Валюта суммы задана, ограничение на валюту выбранной карты отсутствует. | Проверить единицы и область действия правила при каждом допустимом типе входа. |
| B14 | 39, 128 | Номер дня задаёт дату, но не определяет момент исполнения в разных часовых поясах. | Сопоставить расписание с моментом, в который тест должен увидеть результат. |
| B17 | 63–69 | Сценарии приёмки покрывают лишь часть поведения после подключения услуги. | Проверить отдельный наблюдаемый исход каждой основной ветки, включая отказ. |
| B22 | 105 | F-033 цитирует незаполненный адрес Prod. Старое общее описание заглушки не называет окружение. | Показывать поле и конкретное отсутствующее значение в пояснении. |
| B23 | 107 | F-038 цитирует пустое поле Swagger. Оно также попало в F-033. | Сохранять имя поля и различать совпадение цитат и совпадение причин. |
| B25 | 30, 68 | Критерий приёмки предлагает нажать кнопку с другим названием. | Пройти шаги приёмки по описанному экрану и сопоставить действие и подпись. |
| B30 | 24, 40 | Обещание избежать блокировки номера не обеспечивается при пропуске платежа. | Проверить гарантию на конкретной разрешённой ветке отказа. |

B22 и B23 уже локализованы в опубликованном отчёте. Для остальных шести изменены инструкции проверки пропусков и противоречий. После использования автоплатежа для настройки он служит регрессионным примером. Кейс блокировки карты содержит четыре заранее описанных дефекта и позволяет проверить перенос части правил.
